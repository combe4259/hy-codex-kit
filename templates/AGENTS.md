# AGENTS.md

## 작업 순서
1. 계획: 구현 전에 `docs/PLAN.md`를 먼저 채운다. 요구사항이 모호하면 추측하지 말고 질문 목록을 만든다.
2. 테스트: 핵심 동작마다 실패하는 테스트를 먼저 작성한다.
3. 구현: 테스트를 통과하는 최소한의 코드만 작성한다. 요청 범위 밖 기능은 추가하지 않는다.
4. 검증: 테스트를 실제로 실행하고 결과를 확인한 뒤에만 "완료"라고 말한다. 결과는 `docs/VERIFICATION.md`에 남긴다.
5. 커밋: 동작하는 작은 단위마다 커밋한다.

## 커밋
- 한 커밋에 한 가지 변경만 담는다.
- 메시지 형식: `feat: ...`, `fix: ...`, `test: ...`, `docs: ...`, `refactor: ...`
- 테스트가 실패하는 상태로 커밋하지 않는다.

## 기록
- 설계·기술 선택을 할 때마다 `docs/DECISIONS.md`에 결정, 고려한 대안, 근거를 한 항목씩 추가한다.
- 각 단계를 마치면 무엇을, 왜 바꿨는지 3줄 이내로 설명한다.
- 도메인 용어는 처음 나올 때 한 줄 정의를 함께 적는다.

## 실행 환경
- 웹 서버는 반드시 `0.0.0.0`에 바인딩하고, 실행 포트를 출력한다.
- 서버를 띄운 터미널은 종료하지 않는다.
- 개인 API 키나 외부 유료 서비스를 사용하지 않는다.

## 토큰·시간 절약
- 큰 파일은 통째로 읽지 말고 검색으로 필요한 부분만 읽는다.
- 같은 명령을 반복 실행하지 않는다. 오래 걸리는 작업은 시작 전에 예상 시간을 말한다.
- 답변은 짧게. 코드 전체를 다시 출력하지 말고 바뀐 부분만 보여준다.
