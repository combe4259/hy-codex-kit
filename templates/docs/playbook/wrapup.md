# playbook: wrapup

제출 전(종료 15~20분 전)에 사용한다. 새 기능을 추가하지 않는다.

## 점검
0. 사용자가 `/review`를 아직 안 돌렸다면 먼저 권한다.
1. 테스트와 스모크 확인을 마지막으로 한 번 실행하고 결과를 `docs/VERIFICATION.md`에 반영한다.
2. 과제 안내의 필수 파일·파일명·경로가 모두 있는지 확인한다.
3. `git status`로 커밋 안 된 변경이 없는지 확인하고, 있으면 커밋한다.
4. `docs/PLAN.md`의 성공 기준마다 충족 / 부분 충족 / 미충족을 표시한다.
5. `docs/VERIFICATION.md`의 "남은 한계"를 솔직하게 채운다.
6. README에 실행 방법이 최신 상태인지 확인한다.

## 내가 만든 것 요약 (후속 서술형 대비)
사용자에게 아래를 각각 2~3줄로 설명한다. 파일·함수 이름을 함께 적는다.
- 문제를 어떻게 정의했고, 실무자 요구 중 무엇을 우선했나
- 전체 구조와 데이터 흐름
- 가장 중요한 설계 결정 2개와 그 대안, 고른 이유
- 무엇을 어떻게 검증했나
- 남은 한계와 시간이 더 있으면 할 일
- 예상 질문 5개와 핵심 답 한 줄씩
