# playbook: checkpoint

기능 하나를 마칠 때마다 사용한다.

1. 테스트를 실행한다. 출력 마지막 요약을 확인한다.
2. 실행 중인 서비스라면 헬스체크(AGENTS.md의 명령)를 실행한다.
3. 이번 기능이 핵심 제약(동시성, 정확도, 정합성 등)에 관련되면 한 번이 아니라 여러 번 반복 실행해서 매번 지켜지는지 확인한다.
4. 실패하면 여기서 멈추고 원인을 고친 뒤 1번부터 다시 한다. 원인이 바로 보이지 않으면 `systematic-debugging` 스킬을 쓴다. 테스트를 고쳐서 통과시키지 않는다.
5. 통과하면:
   - `docs/PROGRESS.md`에서 해당 기능을 "통과"로 바꾸고 확인 방법을 적는다.
   - `docs/VERIFICATION.md` 표에 한 줄 추가한다 (확인한 것, 방법, 반복 횟수, 결과, 근거).
   - 이번에 내린 설계 결정이 있으면 `docs/DECISIONS.md`에 추가한다. 근거 코드 `파일:라인`, 왜 충분한가, 언제 깨지는가를 포함한다.
   - 실행 방법이나 API가 바뀌었으면 `README.md`를 갱신한다.
6. `git diff --stat`으로 변경 범위를 확인하고 커밋한다 (`feat:` 등 형식, 왜를 포함).
7. 사용자에게 3줄로 보고한다: 무엇을 했나 / 왜 이렇게 했나 / 어떻게 확인했나.
8. 다음 기능은 `test-driven-development` 방식으로 테스트부터 시작한다.
