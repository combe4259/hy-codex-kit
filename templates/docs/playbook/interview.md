# playbook: interview

실무자와 대화하기 전·후에 사용한다.

## 대화 전
1. README와 과제 안내를 읽고, 이미 알 수 있는 사실과 모르는 것을 나눈다.
2. `to-questionnaire` 스킬이 있으면 그것으로 질문 목록을 만든다. 없으면 직접 만든다. 순서: 목적·사용자 → 현재 방식과 불편 → 입력 데이터 → 원하는 결과물 → 성공 판단 기준 → 제약(시간·환경·보안).
3. 질문은 한 번에 하나, 예/아니오가 아니라 구체적 사례를 끌어내는 형태로 쓴다. "이게 실패하면 현장에서 무슨 일이 생기나요?" 같은 질문을 포함한다.
4. 우선순위가 높은 질문 5개 이내만 사용자에게 보여준다.

## 대화 후
1. 사용자가 붙여준 대화 요지를 `docs/PLAN.md`의 요구사항 표로 옮긴다. 출처(대화 요지)를 함께 적는다.
2. 대화에 나온 도메인 용어를 `docs/GLOSSARY.md`에 추가한다.
3. 명시된 요구사항 뒤에 숨은 두 번째 경로를 찾는다. 같은 주체의 동시·중복 요청, 경계값, 부분 실패, 규모 확장 등에서 요구사항이 깨지는 경우를 PLAN 3장 "명시되지 않은 위험 시나리오"에 적는다.
4. 명시되지 않아 직접 정해야 하는 것은 PLAN 6장 "가정"에 결정과 이유를 적는다. 아직 답이 없는 질문은 "미확인 질문"에 남긴다.
5. 요구사항 중 서로 충돌하거나 모호한 것을 짚어서 보고한다.
6. 다음 단계: `define-goal`로 성공 기준을 PLAN에 확정한다. 모호함이 크면 `grill-me`로 점검한다.
